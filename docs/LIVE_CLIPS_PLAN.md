# План модуля «Нарезки в прямом эфире»

> Модуль реализован в 1.1.x. Разбор багов записи эфира в 1.1.0 и исправления:
> [LIVE_RECORDING_FIX_1.1.1.md](LIVE_RECORDING_FIX_1.1.1.md).

Анализ и технический план. Ничего не реализовано — документ для запуска по команде.

## 1. Цели и принятые допущения

- Пользователь вставляет ссылку на идущий стрим — приложение записывает его локально и выдаёт готовые клипы **по ходу эфира**, не дожидаясь конца.
- Задержка клипа **1,5–3 минуты** после окончания момента — принята пользователями.
- Всё локально: без токенов, без облака, без внешних API.
- MVP: **Twitch + Kick**. Второй этап: **YouTube Live**.

## 2. Архитектура конвейера

```
рекордер (HLS) ──> растущая запись (сегменты/файл)
        │
        ├─ лог плейлистов (маркеры рекламы)
        ▼
окно 5 мин (ffmpeg tail → 16 кГц wav)
        ▼
очередь транскрипции (CPU Whisper, чанки 10 мин, watchdog)
        ▼
анализ моментов (абсолютные тайминги эфира)
        ▼
дедупликация по границам окон
        ▼
вырезка из локальной записи → рендер 9:16 → клип в ленте
```

Состояние хранится в SQLite: `streams`, `segments`, `moments`, `queue` — переживает перезапуск приложения.

## 3. Рекордер

- **Вариант A**: yt-dlp в режиме live (HLS) пишет растущий файл. Проще, но нет контроля над маркерами рекламы внутри плейлиста.
- **Вариант B (рекомендуется)**: собственный лёгкий HLS-клиент: раз в ~2 секунды тянет плейлист, скачивает новые медиа-сегменты и **сохраняет снапшоты плейлистов**. Это даёт и запись, и метаданные рекламы, и точный маппинг «время эфира → байты».
- Переподключение: при обрыве — повторный poll, проверка sequence-номеров, пропущенные сегменты помечаются, запись продолжается.
- Хранение: хвост последних N часов (по умолчанию 3), старые сегменты удаляются; опция «сохранить запись целиком».

## 4. Фильтр рекламы — детальный разбор

Twitch вшивает рекламу прямо в HLS-плейлист. Маркеры известны и описаны в открытых проектах ([TwitchAdSolutions](https://github.com/ryanbr/TwitchAdSolutions), [streamlink](https://git.ventilaar.nl/github/streamlink/commit/b8d69b83c415745566cf30f5edfe8f3ceb1a91ce), [yt-dlp issue #1089](https://github.com/yt-dlp/yt-dlp/issues/1089)):

- `EXT-X-DATERANGE` с `SCTE35-OUT/IN` (CUE-OUT / CUE-IN);
- `#EXT-X-CUE-OUT`, `X-TV-TWITCH-AD`, `stitched-ad` — signifier-метки;
- discontinuity-теги и prefetch-сегменты сразу после рекламного блока;
- у yt-dlp встроенной фильтрации нет (манифест передаётся ffmpeg), поэтому метки нужно ловить самим.

### Пайплайн фильтрации

1. Рекордер сохраняет снапшоты плейлистов.
2. Парсер извлекает интервалы рекламы: (start, end) по маркерам и списку сегментов.
3. Интервалы помечаются в базе; окна анализа, пересекающиеся с рекламой, пропускаются или обрезаются.
4. Лог «реклама найдена» виден в интерфейсе; можно вручную пометить «это не реклама».

### Резервные эвристики (если маркеров нет)

- Громкость: реклама стабильно громче контента (EBU R128 по окнам) — порог +4–6 LUFS.
- Чёрные кадры/смена логотипа на границах блока.
- Ключевые слова в распознанном тексте — самый слабый сигнал, только как подсказка.

### YouTube Live

Реклама подключается иначе (прероллы/мидроллы вне HLS или SSAI с другими маркерами), надёжность ниже. В MVP честно помечаем: «реклама не фильтруется», фильтр — отдельным этапом.

## 5. Окно анализа и распознавание

- Окно: 5 минут (настраиваемое 3/5/10).
- Перекрытие соседних окон 60 секунд + дедупликация моментов по пересечению таймингов и близости текста.
- Распознавание: существующий путь — CPU int8, чанки 10 минут, watchdog на часть. Замерено: ~5× быстрее реального времени.

## 6. Очередь и ресурсы

- 1 поток транскрипции, рендеры в очереди (уже есть).
- Политика отставания: если обработка отстала от эфира больше чем на 10 минут — окно увеличивается, старые необработанные окна пропускаются с пометкой, чтобы не копить долг.

## 7. Интерфейс «Стримы»

- Ввод ссылки, статус: время эфира, занято диска, обработано окон, найдено клипов.
- Живая лента клипов (миниатюра, score, таймкод эфира).
- Кнопки: «Стоп», «Сохранить запись», «Клип из последних 60 секунд».
- Настройки: окно анализа, хвост на диске, фильтр рекламы вкл/выкл, задержка.

## 8. Диск (час записи)

| Качество | ≈ размер/час |
|---|---|
| 1080p | 2–4 ГБ |
| 720p | 1–2 ГБ |
| 360p | 0,3–0,6 ГБ |

По умолчанию хвост 3 часа + автоочистка.

## 9. Этапы и критерии приёмки

- **P0 (полдня)**: рекордер + снапшоты плейлистов + окно + транскрипция. Прогнать на реальном Twitch 1 час, зафиксировать маркеры рекламы.
- **P1 (2–4 дня)**: полный конвейер Twitch/Kick, фильтр рекламы по маркерам, вырезка/рендер, экран «Стримы». Критерий: 3+ клипа за час эфира, задержка ≤3 мин, рекламные фрагменты не попадают в клипы.
- **P2**: YouTube Live, уведомления, сохранение записи, статистика.

## 10. Риски и митигация

| Риск | Что делаем |
|---|---|
| Twitch поменял формат маркеров | снапшоты плейлистов — видно, что пришло; обновляем парсер |
| Обрыв сети | авто-reconnect по sequence, пропуски помечаются |
| Отставание от эфира | политика пропуска старых окон |
| Реклама без маркеров | эвристика громкости + ручная пометка |
| Диск забит | лимит хвоста + предупреждение |
| YouTube Live защита | PO-token уже есть; обновления yt-dlp при необходимости |
